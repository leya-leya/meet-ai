# AI 智能会议纪要与内容管理系统 V1.0 — 产品规格

## 1. 产品目标

为公司内部提供一个极简工具，把已有音频或视频文件快速整理成可编辑、可检索、可导出的文字资料。

核心闭环：

> 上传音视频 → 转文字 → AI 摘要 → 内容编辑 → 历史记录 → 导出

V1.0 不追求实时、不追求多人协作、不追求 SaaS 化。

---

## 2. 成功标准

V1.0 只有在以下场景可以完整跑通时才算成功：

1. 用户上传一个支持格式的音视频文件。
2. 系统保存文件并生成记录。
3. 系统完成语音转写。
4. 系统基于转写内容生成摘要。
5. 用户可以编辑摘要与完整转写。
6. 用户可以保存修改。
7. 用户可以在历史记录中再次找到该内容。
8. 用户可以导出 TXT 和 Markdown。
9. 用户可以删除记录和对应本地文件。

---

## 3. 用户角色

V1.0 只有一个默认内部用户。

不开发：

- 用户注册
- 用户体系
- 多角色
- 权限控制

---

## 4. 页面

V1.0 只有三个主页面。

### 4.1 上传页

目的：创建新的内容记录。

页面元素：

- 页面标题
- 文件选择区域
- 支持格式提示
- 最大文件大小提示
- 选中文件名称
- 上传按钮
- 当前处理状态
- 错误提示

用户流程：

```text
选择文件
→ 点击上传
→ 上传成功
→ 创建记录
→ 转写
→ 生成摘要
→ 完成
→ 自动进入详情页
```

处理过程中至少显示：

- 已上传
- 正在转写
- 正在生成摘要
- 已完成
- 处理失败

V1.0 不实现实时进度百分比。

---

### 4.2 历史记录页

目的：重新找到以前处理过的内容。

显示字段：

- 标题
- 原始文件名
- 文件类型
- 创建时间
- 当前状态

功能：

- 按标题关键词搜索
- 点击进入详情
- 删除记录

默认排序：

> 创建时间倒序

V1.0 不做：

- 分页优化
- 标签
- 文件夹
- 批量操作
- 高级筛选

记录较少时允许一次返回全部结果。

---

### 4.3 记录详情页

显示：

- 标题
- 原始文件名
- 创建时间
- 状态
- AI 摘要
- 完整转写文本

可执行：

- 修改标题
- 修改摘要
- 修改完整转写
- 保存
- 导出 TXT
- 导出 Markdown
- 删除

如果记录状态为 `failed`：

- 展示错误提示
- 若已有转写内容，仍允许查看和编辑

---

## 5. 上传规则

支持格式：

- MP3
- WAV
- M4A
- MP4
- MOV

扩展名：

```text
.mp3
.wav
.m4a
.mp4
.mov
```

单文件最大：

```text
500 MB
```

不支持的文件应在后端拒绝。

文件保存时使用唯一内部文件名。

例如：

```text
8c0d7a7e-xxxx-xxxx-xxxx-xxxxxxxxxxxx.mp4
```

同时保存：

```text
original_filename = "杜老师直播0814.mp4"
stored_filename = "8c0d7a7e-xxxx.mp4"
```

---

## 6. 标题规则

新记录标题默认使用：

> 原始文件名去掉扩展名

例如：

```text
杜老师直播0814.mp4
```

默认标题：

```text
杜老师直播0814
```

用户之后可以修改。

标题不能为空。

---

## 7. 转写功能

输入：

- 已保存在本地的音频或视频文件

输出：

- 完整纯文本转写结果

V1.0 不要求：

- 说话人分离
- 时间戳到句
- 多语言翻译
- 实时转写
- 字幕文件
- 自动纠错工作台

如果 ASR 服务失败：

- `status = failed`
- 保存 `error_message`
- 前端显示失败信息

---

## 8. AI 摘要功能

输入：

- 完整转写文本

输出统一为 Markdown 文本，推荐结构：

```markdown
## 内容摘要

一段简洁总结。

## 核心要点

- 要点 1
- 要点 2
- 要点 3

## 待办事项

- 如存在明确行动项，则列出
- 如不存在，写“无明确待办事项”
```

AI 摘要生成后允许人工修改。

V1.0 不自动覆盖人工修改后的摘要。

---

## 9. 内容编辑

详情页允许修改：

- 标题
- 摘要
- 转写文本

点击保存后持久化到 SQLite。

保存成功后给出明确提示。

刷新页面后必须仍能看到修改后的内容。

---

## 10. 历史记录

历史记录数据来自 SQLite。

搜索规则：

- 只搜索 `title`
- 不区分大小写
- 允许部分匹配

默认按：

```text
created_at DESC
```

排序。

---

## 11. 导出

### 11.1 TXT

文件名：

```text
{title}.txt
```

内容：

```text
标题
创建时间
原始文件名

AI摘要
====================

{summary}

完整转写
====================

{transcript}
```

### 11.2 Markdown

文件名：

```text
{title}.md
```

内容：

```markdown
# {title}

- 创建时间：{created_at}
- 原始文件：{original_filename}

## AI 摘要

{summary}

## 完整转写

{transcript}
```

V1.0 不导出 Word / PDF。

---

## 12. 删除

删除一条记录时：

1. 删除数据库记录。
2. 如果本地上传文件存在，则删除文件。
3. 文件已经不存在时，数据库记录仍应能够删除。
4. 删除完成后返回历史记录页。

V1.0 不提供回收站。

---

## 13. 状态模型

合法状态：

```text
uploaded
transcribing
transcribed
summarizing
completed
failed
```

典型流程：

```text
uploaded
→ transcribing
→ transcribed
→ summarizing
→ completed
```

任一步骤失败：

```text
→ failed
```

---

## 14. 错误场景

必须覆盖：

- 没选择文件
- 格式不支持
- 文件超限
- 文件保存失败
- ASR 调用失败
- LLM 调用失败
- 记录不存在
- 保存编辑失败
- 导出失败
- 删除失败

所有错误都必须让用户知道发生了什么。

---

## 15. V1.0 明确不包含

范围外功能以 `AGENTS.md` 为准。

产品层最重要的禁止项：

- 实时会议
- 用户系统
- 多人协作
- 权限系统
- 云盘
- 自动剪辑
- 自动发布
- AI 对话
- 知识库 / RAG
- Word / PDF 导出
- App / 小程序

---

## 16. V1.0 验收用例

使用一个真实 1–5 分钟音频或视频完成：

```text
上传
→ 转写
→ 摘要
→ 编辑
→ 保存
→ 历史记录搜索
→ 重新打开
→ TXT 导出
→ Markdown 导出
→ 删除
```

以上流程全通过，才允许标记 V1.0 完成。
